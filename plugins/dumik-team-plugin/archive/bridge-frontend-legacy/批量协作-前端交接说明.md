# 前端交接说明（给 Codex）

## 一句话任务

给 BatchRefiner **加一个「Agent 模式」**：连本地桥服务，实时显示 Agent 跑详情页流水线的进度和图，设计师在界面里确认方向、选片标注、终审。**原有手动模式全部保留，不删任何现有能力。**

## 必读（按顺序）

1. `批量协作-文件合同.md` —— 三方通信的唯一准绳，字段以它为准，**不要单方改字段名/枚举值**。
2. `批量协作-BatchRefiner改造清单.md` —— 要删/改/加什么、哪些 UI 直接复用。
3. `批量协作-分工.md` —— 边界：你只改前端，不碰 skills 和桥服务代码。
4. 架构图见对话里的「完整架构」一图。

## 背景（角色翻转）

以前 BatchRefiner 在浏览器里自己生图。现在生成、看图自检、校准、QA、修复全在 Agent 引擎；BatchRefiner 的 Agent 模式只做三件事：**看进度、看图、做决策**。生成那套留给手动模式，原样不动。

## 要做的（Agent 模式）

1. **模式切换**：store 加 `mode: 'manual' | 'agent'`，Topbar 加入口。Agent 模式下隐藏「生图/Key 设置/额度」等手动控件；切回手动恢复原样。
2. **桥连接层 `src/lib/bridgeClient.ts`**：连本地桥（见下「接口契约」），订阅 run-state、POST selection，断线重连、首连拉全量。
3. **只读同步**：Agent 模式下 task 数据来自桥，对用户只读；仅选片/标注可写。run-state 已按 `ProjectData` 兼容设计，可走现有 `loadProjectFromJson` / `projectSnapshot` 路径 ingest，再由 bridgeClient 持续打补丁。
4. **进度看板**：复用现有 `GenerationLogSession` + `pipeline.stage` + `stats`，显示「在干嘛 / 到哪步 / 第几张」。可扩展 `DockProgress`。
5. **闸① 方向确认 UI**：pilot 结果页，通过/打回 + 区域标注 → 写 `directionDecision`（含 `annotations`）。
6. **闸③ 终审 UI**：approved/redo → 写 `finalReview`。
7. **选片细化到结果图级**：现有选片到任务级，补 `selectedResultId`，选片写 `imageSelections`。此项手动模式也受益。

## 接口契约（本地桥，默认 `http://localhost:4399`）

桥服务代码在插件 `bridge-server/`（你不用改它，只对接）。

- `GET /api/run-state` → 返回当前 run-state（图片 `src` 已转成 `/files/...` URL，可直接用）。首连兜底用。
- `WS /ws`：
  - 连上后收到 `{ type: "run-state", state }`（全量）。
  - 文件变化时收到 `{ type: "run-state", state }`（推送）。
  - 选片保存成功收到 `{ type: "selection-saved", submittedAt }`。
- `POST /api/selection`，body 为合同里的 selection 片段（可分段提交：先 `directionDecision`，后 `imageSelections`，最后 `finalReview`）。桥会合并写盘。
- 图片：run-state 里的 `src` 已是 `/files/...`，`<img>` 直接用。

字段形状严格按 `批量协作-文件合同.md`。

## 可验证完成标准

- [ ] 有模式切换；手动模式行为和现在**完全一致**（回归不破）。
- [ ] Agent 模式连上桥后，能看到 run-state 推送的任务和图，进度看板随 `pipeline.message`/`stats` 实时变。
- [ ] 闸①：能在 pilot 图上选方向 + 标注，POST 后桥的 `selection.json` 出现 `directionDecision`。
- [ ] 闸②：能逐图选 `selectedResultId` 和 `action`，POST 后出现 `imageSelections`。
- [ ] 闸③：能终审，POST 后出现 `finalReview`。
- [ ] 断网/重连后能自动恢复并拉到最新 run-state。
- [ ] Key 不在 Agent 模式前端出现。

## 不要做

- 不删手动模式的生图、Key、额度、批量、快照能力。
- 不改合同字段名和枚举值（`stage`/`status`/`qaVerdict`/`action` 等）；要改先同步三方。
- 不碰 skills 和 `bridge-server/` 代码（不是你的边界）。

## 怎么自测

1. 起桥服务：`cd bridge-server && npm install && PROJECT_DIR=<某测试项目> node server.js`。
2. 手动在 `<项目>/bridge/run-state.json` 放一份合同示例（文件合同第二节那段），往 `输出/确认图/` 丢几张图。
3. 前端切 Agent 模式连 `localhost:4399`，应看到任务和图、进度。
4. 在前端做选片 → 检查 `<项目>/bridge/selection.json` 是否按合同写出。

不需要真 Agent 在跑，用手摆的文件就能联调前端。
