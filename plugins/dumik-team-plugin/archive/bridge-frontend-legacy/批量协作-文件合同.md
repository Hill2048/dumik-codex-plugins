# 批量协作 · 文件合同

DUMIK 详情页批量出图，Agent（引擎）、本地桥服务、BatchRefiner（前端）三方靠文件通信。本文件定义这套合同。

设计原则：贴着 BatchRefiner 现有 `ProjectData / Task` 模型走，让前端几乎能原样吃进去，不另造一套平行模型。

## 一、项目文件夹结构

在现有项目目录基础上加一个 `bridge/`：

```text
project\<项目名>\
  原图\
  参考\
  输出\
    提示词\
      提示词记录.json        # 已有，grid-card-prompts 产出
    确认图\                  # Agent 生成的候选图落这里
    成品\
    运行记录\
    校准沉淀.json            # 闸① 通过后产物（见第四节）
  bridge\
    run-state.json          # Agent → 前端：进度 + 任务 + 图
    selection.json          # 前端 → Agent：选片 + 标注 + 方向确认
```

桥服务 watch `bridge\` 和 `输出\确认图\`；Agent 只写 `run-state.json`、`校准沉淀.json` 和图片，只读 `selection.json`；前端只读 `run-state.json`、只写 `selection.json`。三方各管各的写，不抢。

## 二、run-state.json（Agent 写，前端读）

Agent 每推进一步、每出一张图就更新它。字段对齐 BatchRefiner 的 Task，前端可近原样 ingest。

```json
{
  "schemaVersion": 1,
  "projectId": "纯钛乌檀木菜板-detail-0001",
  "projectName": "纯钛+乌檀木菜板 详情页",
  "updatedAt": 1733500000000,

  "pipeline": {
    "stage": "batch_draw",
    "sellingPointId": "双面生熟分离",
    "message": "正在批量抽卡：12 张已出 7 张",
    "openGate": null
  },

  "stats": { "total": 12, "running": 3, "done": 7, "failed": 0 },

  "tasks": [
    {
      "id": "卖点A-方向2-cand-1",
      "index": 0,
      "title": "双面生熟分离 · 方向2 · 候选1",
      "description": "全幅候选，机位微调",
      "sellingPointId": "双面生熟分离",
      "directionId": "double-side-direction-2",
      "routeId": "material_macro",
      "status": "Success",
      "progressStage": "rendered",
      "sourceImage": "原图/产品白底图.png",
      "referenceImages": ["参考/设定-结构.png"],
      "promptText": "引用视觉设定的完整中文提示词……",
      "aspectRatio": "9:16",
      "resolution": "2K",
      "imageModel": "banana2",
      "resultImages": [
        {
          "id": "卖点A-方向2-cand-1-r1",
          "src": "输出/确认图/卖点A-方向2-1.png",
          "width": 2048,
          "height": 3640,
          "createdAt": 1733500000000,
          "qaVerdict": "pass",
          "qaNotes": ""
        }
      ]
    }
  ]
}
```

### 字段说明

| 字段 | 含义 | 备注 |
|---|---|---|
| `pipeline.stage` | 当前到哪一步 | 见下方枚举 |
| `pipeline.message` | 一句人话「现在在干嘛」 | 直接显示在进度看板 |
| `pipeline.openGate` | 当前开着哪个闸 | `direction` / `selection` / `final` / `null` |
| `stats` | 进度统计 | 前端进度条用 |
| `tasks[].status` | 任务状态 | 用 BatchRefiner 枚举：`Waiting/Running/Success/Error` |
| `tasks[].sellingPointId / directionId / routeId` | 溯源 | 复盘「哪条 route 有效」用 |
| `tasks[].resultImages[].src` | 图片相对路径 | 相对项目根；桥服务负责转成前端能读的 URL |
| `tasks[].resultImages[].qaVerdict` | Agent 自检结果 | `pass` / `drift` / `reject`；`reject` 的可默认不推前端 |

### pipeline.stage 枚举

```text
planning         视觉设定 + 卖点策略
pilot            试跑 1 个卖点
await_direction  等闸①：设计师确认方向（openGate=direction）
calibrating      吸收校准 → 回写视觉设定 → 重生成各卖点提示词
batch_draw       批量并发抽卡
await_selection  等闸②：设计师全部选完（openGate=selection）
qa               QA 诊断 + 写修复词
repair           批量局部修复
await_final      等闸③：设计师终审（openGate=final）
done             交付
```

## 三、selection.json（前端写，Agent 读）

设计师在前端的所有决策都落这里。Agent 轮询/被通知后读取，对应推进流程。

```json
{
  "schemaVersion": 1,
  "projectId": "纯钛乌檀木菜板-detail-0001",
  "submittedAt": 1733500100000,

  "directionDecision": {
    "sellingPointId": "双面生熟分离",
    "approvedDirectionId": "double-side-direction-2",
    "rejected": [
      { "directionId": "double-side-direction-1", "reason": "把手总变形" }
    ],
    "annotations": [
      { "issue": "镜面反射太碎", "region": "钛面中部", "note": "要宽反射带" },
      { "issue": "品牌区位置偏", "region": "右下角", "note": "视觉设定说在正面居中" }
    ]
  },

  "imageSelections": [
    { "taskId": "卖点A-方向2-cand-1", "selectedResultId": "卖点A-方向2-cand-1-r1", "action": "keep", "notes": "" },
    { "taskId": "卖点B-方向1-cand-3", "selectedResultId": "卖点B-方向1-cand-3-r1", "action": "repair", "notes": "木纹方向反了" }
  ],

  "finalReview": [
    { "taskId": "卖点A-方向2-cand-1", "verdict": "approved", "notes": "" }
  ]
}
```

### 三段对应三个闸

| 字段 | 对应闸 | Agent 拿它干嘛 |
|---|---|---|
| `directionDecision` | 闸① 方向确认 | `annotations` 喂校准沉淀（产品级才传播）；`approvedDirectionId` 决定批量抽哪个方向 |
| `imageSelections` | 闸② 选片 | `action=keep` 进成品候选；`action=repair` 进修复；`action=reroll` 重抽 |
| `finalReview` | 闸③ 终审 | `approved` 进 `输出\成品`；`redo` 回上一步 |

`selectedResultId` 把选片细化到「具体哪张结果图」，不只是任务级（BatchRefiner 现在是任务级选择，要补一个结果图级字段）。

## 四、校准沉淀.json（Agent 写，回写视觉设定用）

闸① 通过后，Agent 把 `directionDecision.annotations` + pilot 经验提炼成产品级校准，回写视觉设定。**只有产品级才传播**，卖点级不写这里。

```json
{
  "schemaVersion": 1,
  "sourceSellingPointId": "双面生熟分离",
  "scope": "product",
  "lockedCorrections": [
    { "part": "把手", "rule": "把手连接处一体成型，不分段，宽度按白底图" },
    { "part": "镜面反射", "rule": "用宽反射带，不要碎反射线" },
    { "part": "品牌区", "rule": "DUMIK 正面居中，不漂移" }
  ],
  "confirmedBaseline": {
    "model": "banana2",
    "size": "2K",
    "aspectRatio": "9:16",
    "sceneMaster": "深色台面 + 侧窗光",
    "referenceUsage": "产品白底图=结构基准，不控整图比例"
  },
  "winningPromptPattern": "场景→核心可见关系→引用视觉设定身份→材质光学→1-2点风险收口",
  "writebackTarget": "输出/提示词/视觉设定.md（校准层）"
}
```

回写后，`calibrating` 阶段用校准后的视觉设定重新生成**所有卖点**的提示词，再进 `batch_draw`。这是「一个卖点对、批量都对」的机制核心。

## 五、和现有插件的衔接

- `grid-card-prompts` 产出的 `提示词记录.json` → Agent 据此填 `run-state.json` 的 `tasks[]`。
- `product-detail-repair` 的修复行 → 由 `imageSelections` 里 `action=repair` 的项触发，结果回写对应 task 的 `resultImages`。
- 图片接口、NAS 参考图、模型路由仍走 `image-batch-agent` 现有脚本，只是改由 Agent 自动调用并把结果落 `输出\确认图\`。
