# 图像提示词（改图 + 视觉 brief）

像美术指导一样写词，不当约束收集器。核心方法：**多图先点名每张图负责什么、单图直接说本次干嘛，再用一段话描述要改成什么，最后用一句短约束收口**。同一组保护规则只写一次，别反复写三遍。

## 执行边界

默认只写可复制的中文提示词、改图指令或视觉 brief。不直接生成图片，不调用 `D-image-run`、图片 API、批量脚本或其他图片工具。

只有用户明确说“生图 / 出图 / 生成图片 / 调用接口”等实际生成意图时，才把确认后的词交给 `D-image-run`；用户只说“写提示词 / 优化 / 改图指令 / prompt / brief”时，必须停在文字交付。

如果用户给的是已有视频、录屏，要拆关键帧、提口播、做图文报告，用 `video-evidence-html-report`（本机另装技能，不在本插件内），不要改写成图片提示词。

## 模式选择

- **改图模式**（有目标图，对现有图做修改）：默认。其下再分：
  - 锁定：保产品结构、角度、构图、比例、SKU 不变。拿不准就用锁定。
  - 创意：允许广告化重构、场景重建，但保产品可识别。
  - 多参考：多张图各管一件事（结构 / 场景 / 局部 / 材质）。
- **洗图模式**（套版/换皮）：给一张参考/灵感图，借它的构图、机位、光线、场景骨架，把产品和风格整体换成我的视觉设定。和改图相反——参考图是被覆盖的骨架，不是要保护的目标。详见下方「洗图模式」。
- **brief 模式**（无目标图或纯创意发散）：KV 概念、场景母体、氛围、材质光影方向。产出美术指导语言；如果最终要落成改图指令，再切回改图模式收尾。

不要把改图任务改写成泛用文生图。

## 写词顺序

内部先回答：图的用途、视觉主角、场景锚点、可见证明关系、SKU 识别点、最可能崩的 1-3 个点。不展示完整内部分析。

最终提示词按这个画面顺序写，保持紧凑：

1. 参考图角色（仅多图）：两张以上才用 `image1 / image2 / image3...` 点名每张图作用；**只有一张图就跳过，别写角色行**。
2. 主指令：一段话写清本次要做什么——保留什么、替换什么、去掉什么、提升什么；不逐图重复解释。单图直接从这里开始。
3. 简短约束：最后一段集中写 3-6 个最关键的禁止项。

约束写法：约束只在最后集中出现一次，不要分散到每一段。先用正向可见描述，再用硬负面词。空话（更高级 / 更好看 / 更有质感）一律换成具体画面方向。

## 无状态防串台

每次写最终提示词都必须按**本轮可见输入**重建：本轮上传的图片、本轮用户文字、本轮已明确指定的产品/文字/比例。不要把上一轮提示词、上一张图内容、上一轮产品细节或聊天里没随本轮一起出现的设定写进代码块。

硬规则：

- 新上传了图片、用户说“这个也用同样思路 / 这张也来一个 / 这个要文字写成...”时，默认是**新任务**；只能复用方法，不复用上一张图的产品、文字、材质、背景、品牌和约束。
- “同样思路”只表示复用工作法：先判断比例、说明图片角色、写主指令、最后短约束；不表示继承上一版的图形、文字、徽章、材质或场景。
- 只有用户明确说“沿用上一版提示词 / 在刚才那张图基础上 / 保持上一张生成结果”，并且上一张图或上一版提示词本轮仍是有效目标时，才允许承接上一版内容。
- 如果上一张图或上一版提示词需要参与生成，必须把它作为本轮真实参考图或明确文本素材重新编号/点名；生图模型看不到聊天记忆，所以代码块里不能写“上一张”“刚才那个”“保持前面”这类上下文词。
- 最终代码块必须自洽：只出现本轮真实存在的 `image1 / image2 / image3...`，不得引用未上传、未编号、未说明角色的旧图。

## 追改 / 二次修改

用户在上一版提示词后说“再加一点…… / 还是不够…… / 改成…… / 这个逻辑不对 / 保持前面但……”时，视为**追改完整提示词**，不是回答解释，也不是只补一句差异。

先判断是不是同一个目标图：没有新目标图、且用户明确要求在上一版继续，才进入追改；如果本轮出现新图片或新目标物，先按「无状态防串台」当新任务处理。

硬规则：

- 必须重新输出完整形状：`比例：...`、必要的图片角色判断、修改要点、最终完整代码块。
- 不要说“在上一版基础上加……”后就结束；代码块里必须是一段可直接复制给生图模型的完整新提示词。
- 同一目标图追改时，只吸收用户新增变量，并保留本任务已经确定的目标图、参考图职责、比例、构图锁定、产品身份锁和关键约束。
- 用户只提一个变量时，只改这个变量的画面语言；不要顺手重写场景、产品结构、比例、镜头或新增无关装饰。
- 如果用户要求“更有金属光泽 / 更清晰 / 更高级 / 更自然”，先翻译成可见光学行为，再并入主指令或简短约束，不要只堆形容词。

追改输出仍按「输出形状」执行。除非用户明确说“只给差异句 / 只告诉我改哪里”，否则默认给完整可复制版本。

## 比例（第一行必写）

最终答复第一行必须只写 `比例：` + 比例池标准比例，例如 `比例：3:4`。第一行不要写依据、解释、约等于、图片尺寸或其他废话。真实图片尺寸只用于内部判断，不输出。最终代码块里的第一行也必须写同一个比例，例如 `比例：3:4`，因为用户复制代码块时模型也要吃到比例。

比例池：1:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9、21:9、1:4、4:1、1:8、8:1。

判断优先级：

1. 用户本次明确指定的比例，且该比例必须落在比例池；如果用户给了非比例池比例，要换算成最近的比例池比例，并说明依据。
2. 当前目标图（“这张图 / 目标图 / 修这张 / 沿用当前图构图”）控制整图比例；先看真实像素，再归一到最近的比例池比例。
3. 用户明确指定的画幅控制者（“以 image4 为背景/场景/母版”）；先看真实像素，再归一到最近的比例池比例。
4. 被编辑图片的真实像素比例；先看真实像素，再归一到最近的比例池比例。
5. 场景母版参考图的比例；先看真实像素，再归一到最近的比例池比例。
6. 平台/用途比例（仅在没有任何图片控制者时）。
7. 默认用 1:1。

硬规则：

- 第一行禁止输出 `1565:2087`、`1024:1536` 这类像素比；只能输出比例池比例。
- 第一行禁止写“依据 image1 / 约等于 / 原始画幅 / 目标图尺寸”等解释。需要判断依据时只在内部使用，不展示给用户。
- 代码块第一行必须重复同一个比例，且同样禁止写依据或解释。
- 真实目标图比例不明时，不许编数字。能查就查图片尺寸，不能查就第一行写“比例：需先确认目标图原始比例（不可猜）”。
- 不要因为是竖图或电商图就猜 4:5。
- 产品白底图、结构图、材质图、logo 图不控制整图比例，除非它本身就是被编辑的目标图。
- 宫格 / 故事板 / 2x2 抽卡：宫格只控制内部排版，不控制整图比例。两层分开写：先整图比例，再内部分区。

示例：外层第一行写 `比例：3:4`，代码块第一行也写 `比例：3:4`。

## 参考图角色

**只有一张图时不写角色行，直接说本次要干嘛。** 两张以上才需要点名分工。角色行只做“短角色卡”，不要把产品细节、文字位置、光影清单都塞进角色说明。

角色行硬规则：

- 每张图只写 1 句，尽量 20-35 字，最多不超过 45 字。
- 只写“这张图是什么 + 本次负责什么”，不要展开长清单。
- `image1` 通常写成“目标图，锁定构图、产品结构、文字和主体位置。”
- 材质 / 光影 / 风格参考只写核心方向，例如“光影质感参考，控制明亮厨房柔光和清透金属高光。”
- “不控制比例 / 不改结构”只在参考图可能误导时短写一次，不要每张图都展开。
- 具体 SKU 细节、文字内容、部件保护、材质光学表现，统一写进主指令和约束里。

固定格式：

```text
图片角色判断：
- image1：目标图，锁定构图、产品结构、文字和主体位置。
- image2：光影质感参考，控制明亮厨房柔光和清透金属高光。
- image3：材质参考，控制表面纹理和反射，不改变 image1 结构。
```

硬规则：

- `image1 / image2 / image3` 必须和用户上传顺序一致；看不清顺序时，先问或按聊天里出现顺序说明“按上传顺序暂定”。
- 角色判断要写“这张图是什么”，例如“image1 是目标图”，“image2 是钛面材质参考”，“image3 是厨房光影参考”。
- 每张图只写核心职责，不要写成长段。特别是 image1，不要把所有 SKU 细节逐项塞进角色行。
- 最终代码块里的提示词正文也必须引用这些编号，不允许只在代码块外解释。执行模型只看提示词时，也要知道每张图的作用。
- 角色说明只写一次，写在提示词开头；后文可以引用 `image1 / image2 / image3`，但不要反复展开每张图的完整职责。

常见角色：

- 目标图：实际被修改的那张。用户含糊时，句子主语或“这张”就是目标图。
- 场景母版：控制背景、光线、相机、构图，通常也控制画幅。
- 产品结构参考：控制轮廓、比例、SKU、五金、部件、角度。
- 材质参考：控制表面、反射、纹理、颜色。
- 局部替换源：logo、徽标、把手、标签、部件。
- 风格参考：氛围、色板、光线性格、摄影语言。

## 产品身份锁

改图必须显式保护 SKU 识别点：轮廓与比例、盖子/顶部结构、把手与握柄、阀钮扣铰链等五金、品牌或 logo 区、材质工艺、配色和 SKU 专属细节，需要时含相机角度和产品姿态。氛围、光线、风格只能支撑产品，不能盖过它。不静默改动这些点。

## 引用视觉设定

项目里有 `输出\提示词\视觉设定.md` 时，产品身份只引用它一句话，别再逐条重写 SKU。视觉设定带图带字：文字是身份锁 + 场景 + 「视觉调性一句话」，图是产品白底/标准图，可直接当一张参考图编号进提示词（如 `image2 = 视觉设定产品图`）。调性当弱牵引统一氛围，不锁构图、不盖产品身份。没有视觉设定再按本文档自己描述身份。

## 品牌文字

- 只有原图、用户请求或画面里已出现 DUMIK 类品牌文字时，才把 **DUMIK** 当标准拼写处理；文字残缺或拼错优先纠正为 DUMIK。
- 用户没提品牌、画面也没有品牌区时，不主动往提示词里加 DUMIK。
- 品牌纠正写成可见文字修正，不写成新装饰元素。

## 洗图模式

给一张别人的好图当版式，把里面的东西换成我的。典型输入：`image1 = 参考/灵感图`，只借它的构图、机位、光比、场景骨架和氛围；我的产品来自视觉设定（`image2 = 视觉设定产品图` + 文字身份）。只有参考图一张、产品靠文字/视觉设定描述时，按单图处理：不写角色行，直接说“做一张类似版式的图，换成……、去掉原图的……”。

主指令一段写清：沿用 image1 的构图、机位、光线和场景结构，把主体换成 image2 的产品（身份按视觉设定锁住），场景和调性对齐我的视觉设定。末尾约束里必有一句：把 image1 原来的产品、logo、文字、品牌元素换干净，只借版式不抄产品。

比例默认跟 image1（留它的版式），除非用户另指定或视觉设定另有画幅。缺产品图或没视觉设定，就先要图或回 `D-detail-plan` 固化设定，别硬猜身份。

## 输出形状

1. 第一行：只写比例，例如 `比例：3:4`（不可跳过，不写依据）。
2. 图片角色判断（仅多图）：两张以上才写，用 `image1 / image2 / image3...` 编号逐张写清“是哪张图 + 负责什么 + 不负责什么”；单图跳过这一项。
3. 修改要点 2-4 条短句。
4. 最终提示词放进代码块，方便整段复制；代码块第一行必须同样写比例：
   - 多图四段式：第一行 `比例：...`，第二段 `image1 / image2 / image3...` 角色说明，第三段主指令一段写完，第四段简短约束。
   - 单图三段式：第一行 `比例：...`，第二段直接写主指令（本次要做什么、保留/去掉什么），第三段简短约束，不写角色行。

用户要“纯提示词”时，只输出代码块里的提示词正文，但正文第一行仍必须是 `比例：...`；多图在比例后保留 `image1 / image2 / image3...` 角色说明，单图在比例后直接写主指令。

## 长度控制

- 多参考图改图提示词默认控制在 250-450 字，复杂产品最多 600 字。
- 图片角色判断默认控制在 1-3 行短句，总字数不超过整段提示词的 20%。
- 同一保护项只写一次；例如“保持 image1 构图/角度/主体位置”写在角色说明或主指令里即可，不要在每段重复。
- 参考图职责、材质替换、清晰度提升、产品保护四类信息要合并表达，避免拆成五六个长段。
- 最后一段约束要短，优先保留真正会坏图的项：不改构图、不改产品结构、不新增物体、不脏污、不塑料感。

简洁示例：

```text
比例：3:4

image1：目标图，锁定俯视构图、主体位置和厨房氛围。image2：菜板材质参考，控制米白边框和雪花钛金属面。image3：台面光感参考，控制暖灰金属台面和柔和反射。

以 image1 为目标图做锁定改图：保持原 3:4 画幅、俯视机位、主体摆放、刀具和三文鱼位置；将菜板替换为 image2 的米白厚实圆角边框与内嵌雪花钛金属面，透视贴合原菜板角度；将台面替换为 image3 的暖灰银色金属台面，并提升整体清晰度、三文鱼新鲜感、菜板边缘、雪花钛纹理和台面反射的真实细节。

约束：不要改变 image1 构图和食材数量，不要改变刀具形状和菜板把手结构，不要让雪花钛覆盖边框或食材，不要做成石材/水泥/塑料台面，不要过度锐化、脏污、噪点或塑料感。
```

## Guardrails

- 不写其他平台的提示词；不把改图任务改写成生成任务。
- 不静默改动「产品身份锁」里的任何一项。
- 保护性文字不许比修改方向本身还长。
- 不发明用户没要的功能和装饰。
- 不承诺参考图撑不住的连续性。

## 模板库（按需读）

大块可套用模板在 [references/templates.md](references/templates.md)：抽象词翻译表、摄影 brief 顺序、材质语言与炊具材质引用块（镜面不锈钢专项）、人物/模特保真案例、人像与皮肤精修（含锁定修皮肤引用块）、空间融合、人手持产品、返修诊断、通用紧凑模板。遇到对应任务先读再写。

每张图角色怎么判断、默认风格底盘见 [references/original.md](references/original.md)。

## 交接

- 用户明确要实际生成：确认后的词交 `D-image-run`。
- 缺视觉设定（产品身份/场景/调性），尤其洗图前：回 `D-detail-plan` 先固化，再回来写词。
- 详情页卖点发散、四宫格抽卡：交 `D-grid-prompt`。
- 抽卡选片后细节漂移：交 `D-image-repair`。
- 路线拿不准：按 AGENTS.md 总监职责重新判断路线。
