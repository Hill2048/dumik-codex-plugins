# 详情页出图策划

这是详情页 AI 出图流水线的源头。先解决“要证明什么、按什么顺序证明、每个卖点怎么用画面证明”，再让下游把它发散成提示词。

这是图片线的转化策划入口，对称于视频线的 `ecom-video-conversion`：视频管卖点顺序和证据链，这个 skill 管详情页的卖点顺序、视觉证据和创意方向。

## 执行边界

默认只输出文字：视觉设定、详情页结构、每卖点视觉证据策略、创意方向。不写最终可提交的抽卡提示词，不调用 `image-batch-agent`、图片 API 或任何生图工具。

- 用户要把单个卖点发散成四宫格抽卡或量产候选：交给 `grid-card-prompts`。
- 用户要把已选定的方向写成可复制改图指令：交给 `image-prompt-optimizer`。
- 用户明确说生图、出图、调用接口：交给 `image-batch-agent`。
- 抽卡选片后产品细节偏了：交给 `product-detail-repair`。

## 第一步：视觉设定

详情页最耗时的不是生很多张，而是每条提示词都重写产品身份。先把项目设定固化成一个可复用的视觉设定，后续所有提示词只引用它，不再重写 SKU。

视觉设定来源优先级：

1. 当前项目 `输出\提示词\视觉设定.md` 已存在：直接复用，不重复生成。
2. 项目 Eagle 图片中心的 `设定` 子文件夹：只读引用，提炼白底、结构、材质、品牌、KV、场景设定。
3. 用户在对话里给的产品描述、参考图、白底图。

视觉设定必须落在 `输出\提示词\视觉设定.md`，包含：

- 视觉调性一句话：先分析本次项目整体的视觉风格、感觉、调性，浓缩成一句可执行的方向描述，放在视觉设定最前面。例如“高端冷调工业感，克制留白，安静厨房里的精密器物，质感优先于热闹”。它是**弱牵引**——给下游一个统一的气质方向，让全套图调性一致，但不锁死构图，也不压过产品身份锁。下游写提示词时把它当氛围底色，不当硬约束。
- 产品身份锁：轮廓与比例、把手与握柄、盖子或顶部结构、五金（阀、钮、扣、铰链）、品牌或 logo 区、材质工艺、SKU 专属色与细节。
- 产品白底图引用：哪一张 `设定` 白底图或结构图是产品结构基准，用于后续抽卡引用和细节修复对照。把它的 Eagle 路径或本地路径写清楚。不要叫它“真值图”，统一叫“产品白底图”。
- 材质语言：每种材质在光下的可见表现，不要停在材质名。例如纯钛写成“克制银灰、低饱和、冷调工业感、干净边缘”；乌檀木写成“深色木纹走向、哑光、纹理可见但不抢主体”。
- 场景母版：详情页统一的背景、台面、光线基调，让全套图视觉一致。
- 参考图角色分配：给每张设定图定一个角色（产品白底图 = 结构基准、形态参考、场景母版、KV 参考等），后续提示词只引用角色，不重写 SKU。品牌国风符号 / 超级符号类图默认不进参考，只有用户特别要求才加入；默认也不要堆参考。

视觉设定是数据文件，不是提示词。它描述“产品是什么样、不能漂移哪里”，不描述某一张图的构图。

## 第二步：详情页结构与卖点编排

吃运营给的卖点清单，先解决信息顺序，再谈画面。

先内部回答：

1. 用户进详情页第一眼要先理解什么？
2. 接下来最可能怀疑什么？
3. 哪个可见证据能消除这个怀疑？
4. 哪个使用利益值得优先记住？
5. 详情页结尾要留下什么品牌记忆？

编排规则：

- 一个卖点对应一个画面任务，不要一张图塞多个卖点。
- 强卖点优先，砍掉不改变认知或决策的弱卖点。
- 详情页是一条转化序列：先认知，再信任，再使用愉悦，再差异化，最后品牌收尾。

## 第三步：每卖点的视觉证据策略

这是这个 skill 的核心产出，也是下游抽卡的蓝图。对每个保留的卖点，写清：

- 卖点要证明的判断：一句话，用户看完该信什么。
- 视觉证据：用什么可见的场景、动作、对比、细节特写来证明。把抽象卖点翻成可见画面，例如“耐用”写成“刀在板面剁击、板面无明显刀痕的特写对比”，而不是写“耐用”。
- 画面角色：主体是产品、人手、材质特写、使用场景还是对比关系。
- 3 到 4 个创意方向：同一个卖点的不同表达方式，供四宫格抽卡探路。只写方向差异（视角、场景、对比手法、构图），产品身份统一引用视觉设定，不重写。
- 比例依据：这个卖点画面用什么比例，依据是什么（详情页通用竖版、对比图、特写）。

## 输出

返回：

1. 视觉设定状态：复用已有 / 本次从设定生成 / 缺设定需补。
2. 详情页核心转化障碍。
3. 卖点模块顺序表：模块、卖点、要证明的判断、主视觉证据。
4. 每个卖点的视觉证据策略 + 3 到 4 个创意方向。
5. 交接说明：哪个卖点先抽卡，怎么交给 `grid-card-prompts`。

## 交接

- 选定要先做的卖点后，把该卖点的视觉证据策略和创意方向交给 `grid-card-prompts` 段一，生成 2x2 四宫格抽卡提示词。
- 编排顺序一旦确定就锁住；下游发散提示词时不重新设计详情页结构，只在单个卖点内展开。
- 视觉设定路径要一并交给下游，让抽卡引用同一份产品身份。

## 批量协作合同（Agent 模式）

在 `ecom-detail-autopilot` 串跑时，本 skill 额外负责**校准回写视觉设定**。这一段无论纯 Codex 内跑还是接前端都生效（`校准沉淀.json` 与回写视觉设定是文件操作，跟前端无关）。合同字段见 `assets/批量协作-文件合同.md`。

- 闸① 通过后，读 `输出/校准沉淀.json`（`scope=product`：`lockedCorrections`、`confirmedBaseline`、`winningPromptPattern`），把这些**产品级**校准并进 `视觉设定.md` 的「校准层」。
- 只吸收产品级（身份锁、材质光学、画幅光线、模型参数、参考图用法）；卖点级构图不进视觉设定。
- 回写后，视觉设定即为后续所有卖点重生成提示词的基线。
- 手动逐步链路不涉及校准沉淀，本段只在 Agent 模式生效。
