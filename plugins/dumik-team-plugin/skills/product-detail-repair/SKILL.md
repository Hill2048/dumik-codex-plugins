# 产品细节修复

## 只做三件事

1. 先分诊：`passed / blocked / reroll`
2. `blocked` 才修：只修局部漂移，不动主体结构
3. 修完复核：最多两轮

## 分诊

- `passed`：没明显偏差，直接进终审
- `blocked`：局部偏了，但整体结构还对，进修复
- `reroll`：轮廓 / 比例 / SKU 结构错，回抽卡重出

## 怎么修

- 对照产品白底图，找真正偏的区域
- 只切局部，不整图重生
- 用 banana2 + 产品白底图写局部修复词
- 视觉判断时先融入比例池，基础框应尽量已经接近目标比例
- 脚本只做轻微外扩和轻微比例纠正，不负责大幅改框
- 遇到遮挡时，按想要的完整零件占位给框，多拆一些，不只框可见部分
- 保持周边光线、色温、接缝一致，方便贴回
- 框先由视觉判断给出，脚本只负责按框切图 / 贴回，不参与看图判断

## 批量

- 多图多区域时，先写 `修复清单.json`
- 跑 `crop-batch -> image-batch-agent -> paste-batch`
- `passed` 跳过，`reroll` 不进修复
- `box` 由视觉判断先给，脚本只吃框，不做识别
- 拆件时：视觉按比例池给基础框 -> 脚本轻微外扩 / 轻微纠正 -> 输出矩形图

## 复核

- 跑完先生成联系表，不看日志当成功
- 逐个看：是否切到目标、是否歪、是否漏主体、是否多带无关大块
- 有问题就改基础框，不改脚本
- 复核后重跑，直到联系表里每个切片都可用
- 被遮挡的零件，按“想要的完整占位”复核，不只看可见部分

## 交接

- 修复词交给 `image-batch-agent`
- 明确用 banana2
- 缺产品白底图，先回 `ecom-detail-planner`
- 整体构图要重做，交 `image-prompt-optimizer` 或 `grid-card-prompts`
