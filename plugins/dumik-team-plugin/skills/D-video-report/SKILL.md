# 视频证据报告

把已有视频整理为可交互复查的 HTML：原片、关键帧、时间点、口播或字幕、镜头结构和结论必须互相对应。

## 入口与归档

先按插件根 `assets/project-env-protocol.md` 判断是否进入项目，并复用 `assets/verified-environment-checklist.md`，不要每次做全量环境检查。

- 已有当前项目：默认沿用，不重复问项目名。
- 项目制默认报告：`输出\提示词\视频拆解报告\<视频名>\index.html`。
- 抽帧、音频、转码和检测文件：`输出\临时\视频拆解\<视频名>\`。
- 运行参数、失败记录和转写来源：`输出\运行记录\`。
- 用户指定输出目录时以用户路径为准；单次任务不强行建项目。

## 执行

1. 确认真实视频路径和分析目标。读取时长、分辨率、帧率、音轨和字幕轨。
2. 检查 `ffmpeg`、`ffprobe`；需要本地关键帧下载数据时再检查 `node`。缺失工具按项目环境协议自动安装并复查。
3. 按目标选粒度：
   - 普通报告：按画面变化初筛，再人工保留关键节点；不要把机械等间隔抽帧当最终证据。
   - 逐镜拉片：按真实剪辑点划镜头，每镜默认保留 A/B 两帧，分别证明镜头建立与动作结果。
   - 教程/界面录屏：按操作状态、字幕变化和结果画面取证。
4. 有字幕先读取字幕；有可靠转写能力再转写音频。听不清、看不清或无法验证的内容标为“不确定”，不能补写。
5. 生成中文 HTML，至少包含：来源与处理范围、关键结论、证据说明、带时间点的口播/字幕、关键帧时间线、镜头或卖点结构、可复用结论和不确定项。
6. 长时间线或用户要求交互回看时，读取 [交互报告规范](references/interactive-report.md)。需要 `file://` 下载关键帧时运行：

```powershell
node plugins\dumik-team-plugin\skills\D-video-report\scripts\build_frame_download_data.mjs <report-dir>
```

7. 打开成品检查图片和视频路径、中文排版、宽窄屏布局；真实点击一次播放定位、结构跳转和图片下载。

## 分析纪律

- 每条判断必须能指向时间点、关键帧、字幕或音频证据。
- 原片只支持分析，不自动改写成新脚本；需要重新规划卖点顺序交给 `D-video-plan`。
- 需要把分析转成新故事板、关键帧或逐镜提示词交给 `D-storyboard`。
- 需要真实生成视频交给 `D-video-run`。
- 不提交 Dreamina、Veo 或图片接口，不把长视频逐字稿整段塞进页面。

## 完成标准

- 用户能从 HTML 看清视频讲了什么、证据在哪里、每个关键镜头发生了什么。
- 页面引用文件全部存在，时间跳转准确，关键帧可下载，移动端无明显重叠。
- 报告明确写出转写/字幕依据和无法确认的内容。
