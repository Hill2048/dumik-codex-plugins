# 视频证据报告

把已有视频整理为可交互复查的 HTML：原片、关键帧、时间点、口播或字幕、镜头结构和结论必须互相对应。

## 入口与归档

先按插件根 `assets/project-env-protocol.md` 判断是否进入项目，并复用 `assets/verified-environment-checklist.md`，不要每次做全量环境检查。

- 已有当前项目：默认沿用，不重复问项目名。
- 项目制默认报告：`输出\提示词\视频拆解报告\<视频名>\index.html`。
- 抽帧、音频、转码和检测文件：`输出\临时\视频拆解\<视频名>\`。
- 运行参数、失败记录和转写来源：`输出\运行记录\`。
- 用户指定输出目录时以用户路径为准；单次任务不强行建项目。

## 执行

1. 确认真实视频路径和分析目标。读取时长、分辨率、帧率、音轨和字幕轨。
2. 检查 `ffmpeg`、`ffprobe`；需要本地关键帧下载数据时再检查 `node`。缺失工具按项目环境协议自动安装并复查。
3. 按目标选粒度：
   - 普通报告：按画面变化初筛，再人工保留关键节点；不要把机械等间隔抽帧当最终证据。
   - 逐镜拉片：按真实剪辑点划镜头，每镜默认保留 A/B 两帧，分别证明镜头建立与动作结果。
   - 运镜复刻：先找真实切点，再对每镜加密抽帧；分别记录摄影机实体位移、观看方向修正、旋转轴与画面方向、推进关系、偏轴漂移、视差和非线性速度曲线。
   - 教程/界面录屏：按操作状态、字幕变化和结果画面取证。
4. 有字幕先读取字幕；有可靠转写能力再转写音频。听不清、看不清或无法验证的内容标为“不确定”，不能补写。
5. 按 [报告数据协议](references/report-data-schema.md) 写 `report-data.json`，不要临场重写页面结构。然后用固定模板构建：

```powershell
node plugins\dumik-team-plugin\skills\D-video-report\scripts\build_report_page.mjs <report-dir> <report-data.json>
```

6. 所有报告默认使用 `assets/report-template/`：顶部结论与指标、左侧原片、右侧逐镜证据、字幕搜索、关键镜头筛选、可复用结论。长时间线或交互细节读取 [交互报告规范](references/interactive-report.md)。需要 `file://` 下载关键帧时运行：

```powershell
node plugins\dumik-team-plugin\skills\D-video-report\scripts\build_frame_download_data.mjs <report-dir>
```

7. 打开成品检查图片和视频路径、中文排版、桌面双栏与移动端底部回看；真实点击一次时间定位、结构跳转、筛选、字幕搜索和图片下载。

## 复合运镜证据

用户要参考视频的构图、运镜、节奏或深度视频轨迹时，不能只输出“推近、环绕、横移”这样的单动词标签。

每个真实镜头至少判断：

- 摄影机从哪里移动到哪里，主路径是直线、浅弧、圆弧还是螺旋。
- 镜头始终看向什么，是否同时发生偏航、俯仰或光轴滚转。
- 画面参照物以什么轴心顺时针或逆时针移动；必要时再写摄影机本体的等效方向，不能混用口径。
- 主体占比如何变化，变化来自实体接近、焦距变化还是无法确认。
- 前景、中景、背景的位移速度是否不同，是否存在偏轴漂移和径向视差。
- 位移速度、推进速度和角速度分别何时缓起、加速、达到峰值、减速和停住；它们可以在不同时间收速。

分析流程：

1. 用场景变化和相邻帧确认真实剪辑点，切点两侧分别建轨迹，不能把硬切解释成连续飞行。
2. 对快速变化段加密抽帧。等间隔联系图只负责全局覆盖，不足以证明峰值和先后关系。
3. 可用光流、局部运动向量或特征拟合辅助估计平移、旋转和缩放趋势；算法输出必须与稳定参照物和关键帧目视结果交叉核对。纹理重复、深度图低对比或运动模糊导致冲突时，报告冲突而不是制造精确数值。
4. 同时发生的运动写在同一时间段。例如拉近期间仍在旋转，应记录为一条连续复合轨迹，不能拆成“先转、再拉”。
5. 只有证据充分时才报告角度、倍率或每秒速度；否则使用缓起、加速、峰值、减速等相对描述。

交给 `D-storyboard` 时使用以下字段：

```text
镜头时间段 / 切点：
摄影机起点与终点：
主路径与观看目标：
同步运动分量：
旋转轴与画面方向：
推进 / 主体占比：
视差 / 偏轴 / 焦点：
速度曲线：
结束状态：
证据与不确定项：
```

## 模型参考联系图

只有当抽帧联系图还要上传给图片或视频生成模型时，执行以下额外规则；普通 HTML 报告不受此节约束：

- 先读取目标平台当前显示的上传限制。Seedance 界面要求参考图为 `1:2.5` 到 `2.5:1` 时，最终文件必须满足 `0.4 <= width / height <= 2.5`。
- 在加入间隔、镜号、时间码后重新读取最终像素宽高并计算 `width / height`；不能只用单帧比例估算。超限即失败，不要把文件交给用户继续试错。
- 超限时重新排列网格，不拉伸、不压扁、不裁掉关键内容。时间线仍按从左到右、从上到下连续排列。
- 15 张横版帧优先排成 `3 x 5`，避免 `5 x 3` 造成超宽，也避免 `4 x 4` 多出的空白格被模型误判为黑场或结尾停顿。
- 旧联系图已经压缩、模糊或比例错误时，回到原视频重新抽帧；不要在旧联系图上二次裁切、放大或重复编码。
- 交付时报告最终尺寸、`width / height` 数值、目标平台允许范围和帧数，并目视确认镜号、时间码、画面顺序与最后一帧均正确。

## 分析纪律

- 每条判断必须能指向时间点、关键帧、字幕或音频证据。
- 运镜结论必须能指向至少两个相邻时间点；“旋转仍在继续”“开始减速”等变化判断应有加密帧或运动估计支持。
- 原片只支持分析，不自动改写成新脚本；需要重新规划卖点顺序交给 `D-video-plan`。
- 需要把分析转成新故事板、关键帧或逐镜提示词交给 `D-storyboard`。
- 需要真实生成视频交给 `D-video-run`。
- 不提交 Dreamina、Veo 或图片接口，不把长视频逐字稿整段塞进页面。
- 不另造视觉模板，不使用渐变、玻璃拟态、发光边框、装饰动画或大面积同色卡片；报告视觉服从证据阅读。

## 完成标准

- 用户能从 HTML 看清视频讲了什么、证据在哪里、每个关键镜头发生了什么。
- 页面引用文件全部存在，时间跳转准确，关键帧可下载，移动端无明显重叠。
- 报告明确写出转写/字幕依据和无法确认的内容。
- 用作生成模型参考的联系图已回读最终像素尺寸，宽高比位于目标平台允许范围内，且没有会改变时间含义的空白格。
