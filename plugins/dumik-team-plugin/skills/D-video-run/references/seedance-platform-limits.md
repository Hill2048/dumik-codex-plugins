# Seedance 执行限制参考

来源参考：MapleShaw/seedance2.0-prompt-skill，commit a2ab7fd，并结合本地 `D-video-run` 既有规则消化。

## 使用边界

本文件只给 `D-video-run` 做提交前检查参考。真实可用参数仍以当前 `dreamina <subcommand> -h` 和项目最新文件为准。

## 提交前必须确认

- provider：Dreamina 还是 Veo。
- 模式：`multimodal2video` / `image2video` / 其他当前 CLI 支持模式。
- 模型：例如 `seedance2.0fast_vip`，但必须以当前命令 help 为准。
- 比例：用户或最新项目文件优先。
- 时长：用户或最新项目文件优先。
- 分辨率。
- 参考图、参考视频、参考音频数量与角色。
- 是否会消耗积分或额度。

## Dreamina 默认

DUMIK 当前默认仍是：

- 命令：`dreamina multimodal2video`
- 模型：`seedance2.0fast_vip`
- 分辨率：`720p`
- 数量：每条 1 个
- 输出：先确认片，再成片

不要因为参考项目写了 Seedance 2.0 通用默认，就改掉本 skill 的执行默认。

## 多模态参考

提交前检查：

- 图片、视频、音频是否真的存在。
- 参考素材角色是否写清。
- 视频和音频时长是否在当前 CLI 支持范围内。
- 参考视频过长时，先裁剪或换轻量版本。
- 上传报 502 或 VOD 失败时，只做一次 5 秒内、无音频、H.264、小体积 fallback。

## 提示词检查

提交前必须检查：

- 是否写明比例、时长、参考来源。
- 是否只有一个主动作和一个镜头运动。
- 是否保护产品结构、材质、比例和品牌区。
- 是否没有把多个无关镜头塞进一条任务。
- 是否没有要求画面生成字幕、水印、额外品牌。
- 如果来自分镜板，是否写明不复刻边框、编号、格线、注释文字。

## 异步预期

Seedance / Dreamina 视频通常是长任务。

- `Queueing`、`Generating`、`querying` 不算失败。
- 不要几分钟没结果就判定卡死。
- 轮询要温和，后续间隔可放到 60-180 秒。
- 提交成功后先记录 `submit_id`、状态、输出路径和实际提交参数。

## 停止条件

以下情况要停：

- 登录或授权失败。
- 明确余额不足。
- 合规确认要求用户去网页处理。
- 同一个参考视频 fallback 后仍上传失败。
- 最新项目文件与提示词记录冲突，且用户没有确认以哪个为准。
- 任务明确返回 fail。

## Veo 分流提醒

Veo 只在用户明确选择时使用。

DUMIK 主文件已有硬限制：

- 不接参考视频和参考音频。
- 只用 `16:9` 或 `9:16`。
- 时长只用 `4`、`6`、`8` 秒。

需要 `3:4`、5 秒、音频/视频参考时，继续走 Dreamina。
